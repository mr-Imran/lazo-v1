# LAZO — Usage guide for the features built on 26 September 2026

Date: 2026-09-26
Covers: the six PRD V1 streams integrated today (see `WORKLOG.md`, session "PRD V1 gaps — six streams") plus the accents stylesheet fix.
Audience: whoever sets up, tests or operates these features (founder, ops, the next developer).

Every feature below is real code that calls the real provider. Nothing is faked: when a migration is not applied or an env var is missing, the API answers **503** with a message naming the exact file or variable, and the UI shows a "not configured" state. So the order of work is always: **apply migrations → set env → restart → use**.

## 1. Core event flow additions

### 1.1 Anonymous draft and claim
- **What a visitor does:** fills `/start/details` without an account. The answers are saved server-side as an `events` row in state `anonymous_draft` and the browser keeps `{id, token}` in localStorage `lazo.anonDraft`.
- **What happens at sign-up:** `/auth/complete` claims the draft (sets the owner, picks the subdomain, state becomes `draft`). If the claim fails, the old sessionStorage path still works.
- **Limits:** 20 drafts per hour per IP. Unclaimed drafts expire after 30 days and are deleted when next read.
- **Admin:** dashboard → Events shows them with state `anonymous_draft`.
- Routes: `POST /api/drafts`, `PATCH /api/drafts/:id`, `GET /api/drafts/:id?token=`, `POST /api/drafts/:id/claim`.

### 1.2 Invoices
- Every successful plan payment (`event_fee`) creates an invoice numbered `LAZO-YYYY-000001…` with IVA 16 % shown as included.
- **Host:** `/dashboard/events/:id/upgrade` → Invoices list → opens `/invoices/:id` (printable; the browser's Print saves a PDF). The host can add RFC, razón social and uso de CFDI there.
- **Admin:** dashboard → Invoices.
- Payments made before today get an invoice the next time their session is synced: `POST /api/admin/payments/:id/sync`.
- **Not built:** CFDI stamping. A PAC (Facturama, SW Sapien) is needed for a fiscally valid factura.

### 1.3 After the event
- Page: `/dashboard/events/:id/after`, linked from the event overview once the date has passed or the event is closed.
- Tick who came (`guests.attended`; also a column in the guest CSV), see gifts and thank-you progress, jump to pending photos, download the guest list, and **Close event**.
- Closing sets `closed_at`. The site stays live; RSVP shows as closed to guests.

### 1.4 PWA
- Production builds register `public/sw.js` on the app host only (never on event-site subdomains, never in dev).
- App shell is precached; `/api/*` is network-first (only `event-types`, `home*`, `sites/by-slug/*` GETs are served stale, max 5 minutes); hashed assets are cache-first; `offline.html` shows when there is no connection.
- Install: Chrome/Edge show "Install LAZO" from the address bar; iOS Safari → Share → Add to Home Screen.
- To force clients to drop old caches, bump `VERSION` in `sw.js`.

### 1.5 Seating export and print
- Seating page → **Export CSV** (`GET /api/events/:id/seating/export.csv?event=<subEventId>`; omit for all celebrations) and **Print plan** (`/print/:eventId/seating`).

## 2. Vendor payments (Stripe Connect)

Lazo is a Connect platform. Vendors get Express accounts (Mexico, MXN). Host payments are destination charges: Lazo's commission is the application fee, the rest transfers to the vendor and Stripe pays them out.

### 2.1 Stripe setup (once)
1. Stripe dashboard → Connect → enable, Express accounts, Mexico.
2. Enable OXXO and SPEI payment methods if wanted.
3. Create **two** webhook endpoints, both pointing at `https://<api>/api/webhooks/stripe-connect`:
   - an *Account* endpoint for `payment_intent.succeeded`, `checkout.session.*`, `charge.refunded`, `charge.dispute.*`;
   - a *Connect* endpoint for `account.updated`.
   Put both signing secrets in `STRIPE_CONNECT_WEBHOOK_SECRET`, comma-separated.
4. Live mode needs Lazo's own KYC completed before live Express accounts can be created.

### 2.2 Vendor
- `/vendor` → **Payments** → *Set up with Stripe* opens Stripe's onboarding; returns to `/vendor?tab=payments&onboarded=1`. *Check status* re-reads Stripe; *Open Stripe dashboard* opens the Express dashboard.
- `/vendor` → **Quotes & orders**: write a quote for an inquiry (line items, optional deposit, valid until, note), save as draft or send (sending requires charges enabled), withdraw. Orders: Start, Mark fulfilled, Refund (full or partial; a real Stripe refund that reverses the transfer and Lazo's fee pro rata).

### 2.3 Host
- `/dashboard/events/:id/orders` (overview card "Quotes & orders"): quotes received → **Accept and pay** creates the order and opens Stripe Checkout (card, OXXO, SPEI). Back on the page the order shows Paid with a receipt link. Decline, Pay again, Cancel unpaid, and refund/dispute state are shown.

### 2.4 Admin
- dashboard → **Vendor orders**: filters, totals (gross, Lazo fees, refunds, disputed, net to vendors), per-vendor settlement, admin refunds, commission % (row `services.vendor_commission_pct`, default 10 %), and **Reconcile with Stripe** for a date range (max 92 days) listing mismatches.

### 2.5 Test walk (test mode)
Vendor approved → Payments → Set up with Stripe → host requests a quote in Find vendors → vendor sends the quote → host Accept and pay with card `4242 4242 4242 4242` → order shows Paid → vendor Start / Mark fulfilled / Refund → admin Vendor orders → Reconcile.

**Not built:** charging the balance after a deposit (settled outside Lazo), host notification on a new quote, dispute evidence upload (use the Stripe dashboard).

## 3. WhatsApp Business (Meta Cloud API)

### 3.1 Meta setup (once)
1. Meta Business verification; a WhatsApp Business Account with a **production** phone number (not the test number).
2. A permanent System User token with `whatsapp_business_messaging` and `whatsapp_business_management` → `WHATSAPP_ACCESS_TOKEN`; copy the phone number id and WABA id.
3. Webhook: callback `https://<api>/api/webhooks/whatsapp`, verify token = `WHATSAPP_WEBHOOK_VERIFY_TOKEN`, subscribe to `messages` and `message_template_status_update`. App secret → `WHATSAPP_APP_SECRET`.
4. dashboard → **WhatsApp** → *Submit to Meta* for `lazo_invitation` and `lazo_reminder`, then *Sync from Meta* until they show `approved`. Nothing can be sent before that.

### 3.2 Consent
- Guests tick "Recibir avisos por WhatsApp" on the RSVP form (with a phone). Hosts see a WA pill per invitation on the guest list and can toggle consent by hand. A guest who replied STOP/BAJA/ALTO is opted out and cannot be re-opted by the host.

### 3.3 Sending (Premium plan)
- `/dashboard/events/:id/messages` → channel **WhatsApp** → pick an approved template, audience, check the preview (rendered from a real recipient), send. The table below shows accepted / sent / delivered / read / failed per invitation with Meta's error title.
- Sends go only to consenting, non-opted-out households; 10-digit Mexican numbers get +52.

### 3.4 Admin
- dashboard → WhatsApp: templates with Meta status, submit, sync, and failures in the last 7 days.

**Not built:** automatic retry of transient failures, editing template bodies from the admin (edit the `whatsapp_templates` row), media/button templates.

## 4. Retailer catalogs and fulfilment partners

### 4.1 Retailers (Amazon MX, Mercado Libre)
- Credentials: Amazon Associates MX + Product Advertising API keys; a Mercado Libre app (client credentials). Put the Mercado Libre affiliate id in `retailers.affiliate_tag` once approved.
- **Host:** builder Gift step → *Search a store* → pick a retailer, search, **Add**. Items show In stock / Out of stock; *Refresh prices & stock* re-checks them.
- **Guest:** "View gift" on the site goes through `GET /api/sites/:slug/registry/:itemId/go`, which records the click and redirects to the tagged store page. "I bought this" remains the reservation.
- Smoke test after keys: `GET /api/retailers` shows `configured: true`; `GET /api/retailers/amazon_mx/search?q=licuadora`.
- **Not built:** buying inside Lazo (neither store sells on a third party's behalf), group contributions.

### 4.2 Fulfilment partners (print, flowers, travel)
- **Admin first:** dashboard → **Fulfilment** → add a contracted partner: category, contact, cities covered, products with price/unit/lead days, notify by email or signed webhook (rotate secret there). Nothing is seeded; without a partner hosts only see the manual concierge fallback.
- **Host:** `/dashboard/events/:id/concierge` → *Order from a partner* → city → partner → product → quantity, address, needed-by date → order. Orders list shows the timeline; **Cancel** is allowed while submitted or confirmed.
- **Partner:** replies by email, or its system calls `POST /api/partners/fulfilment/:orderId/status` with `X-Lazo-Signature: sha256=<HMAC of raw body>`. Statuses: submitted → confirmed → in_production → shipped → delivered, or rejected.
- **Admin:** orders board, status with note, payment status (unpaid/paid/refunded by hand), partner reference.
- **Not built:** collecting payment for partner orders, print proof approval, travel itinerary acceptance.

## 5. Corporate and memorial modes

> Launch focus (2026-09-26): only **Wedding** and **Baby Shower** are active. Corporate and memorial are built but inactive; set `event_modes.active = true` to turn one on. After applying the focus migration, upload a Baby Shower card image (dashboard → Homepage) and add at least one theme for `baby_shower` (dashboard → Themes).

- Configuration lives in `event_modes`: `vocabulary` (labels per mode, es/en), `privacy_defaults`, `sections` (ordered site sections). Change a mode by updating its row.
- Defaults applied at creation: corporate → uploads off, guest count hidden, no registry; memorial → password required, not searchable, uploads off; bautizo → password required.
- **Host:** builder → Event Info shows the mode's sections (corporate: Agenda, Speakers, Materials; memorial: Life, Service, Donations). Go Live blocks Publish until a required password is set. Memorial events get a **Messages of condolence** card on the overview (`/dashboard/events/:id/condolences`) to approve or delete messages.
- **Site:** the default page and the Red Theme render the mode's sections in order and hide RSVP, registry or photos when the mode lacks them. Condolence form is public; messages show only after approval.
- `GET /api/event-types` exposes all of this to the frontend; `GET /api/events/:id` returns `privacy`.

## 6. Mercado Pago (second gateway for plan fees)

- Setup: Mercado Pago application with production credentials → `MERCADOPAGO_ACCESS_TOKEN`; webhook `https://<api>/api/webhooks/mercadopago`, topic Payments → `MERCADOPAGO_WEBHOOK_SECRET`; `API_URL` must be the public https base (used as `notification_url`). OXXO/SPEI depend on the account; edit `payment_gateways.methods` if a method is not enabled.
- **Host:** `/dashboard/events/:id/upgrade` shows a gateway chooser only when more than one gateway is configured, with each gateway's methods. Return from Checkout Pro lands on the overview with `?gateway=mercadopago&payment_id=` and confirms automatically.
- **Admin:** dashboard → Payments: gateway column, **Refund** per settled purchase (a full refund removes the plan), **Reconcile** for a date range per gateway.
- `PAYMENTS_DEFAULT_GATEWAY` picks the default when the host does not choose.

## 7. Analytics warehouse

- Lives in Postgres schema `analytics` (not exposed to PostgREST; the backend reads it via `DATABASE_URL`). Keep the schema out of Supabase's exposed schemas list.
- **Ingest:** runs automatically every 6 hours (first run about a minute after boot), or dashboard → **Analytics** → *Run now*. Alternative: enable the commented `cron.schedule` in the migration and set the interval env to `0` (use one, not both).
- **Dashboard:** KPI tiles (funnel, RSVP rate, gifts, revenue by gateway, Lazo revenue vs GMV, refunds, vendor leads, delivery rate, chat first response, photos), a chart per metric, ingest status and freshness, reconciliation table, date range.
- **Revenue reconciliation:** *Reconcile* for a range compares warehouse payments with Stripe balance transactions and Mercado Pago payments; rows are `ok`, `mismatch` or `unchecked` (no token). Stripe fees are written back so provider cost is real.
- Per-event daily series: `GET /api/events/:id/analytics/daily?from&to`, served only when the last ingest is under 30 hours old.
- Days are UTC. Acquisition source is not tracked (no source data).

## 8. Frontend styling note

`lazofrontend/src/accents.css` loads before the page stylesheets, so every selector in it is prefixed with `:root` to win. The event overview cards are coloured by position (1–13) and the "Open your site" card by class. If you add a card, add a matching `:nth-child` rule with a tint and icon.
